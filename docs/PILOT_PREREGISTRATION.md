# Preregistered pilot protocol — RTT-PILOT/1

**Status:** SPECIFIED / NOT RUN. This document describes a proposed 24-trial feasibility pilot. It is **not** an empirical result, a proof of human or machine intelligence, or a claim about actual model-to-model KV sharing.

Version: 2026-11-10. This design is frozen for any run labeled RTT-PILOT/1. Deviations must be logged and cannot retroactively redefine a successful trial.

## Research question

Can a machine conductor distinguish human origin from the absence of a private communication channel, after observing a machine-only baseline?

**Primary hypothesis (testable, not established):** In machine-to-machine replacement controls, removing an otherwise available private *text* channel increases the conductor's reported probability of a human replacement. If it does, the conductor may be responding to connectivity rather than human identity.

This is a *software side-channel* pilot. A successful result would **not** demonstrate SwaT-style KV transfer, telepathy, consciousness, or intelligence.

## Assignment structure — 24 trials

The first 20 trials cover 2 × 2 factorial conditions, five independent trials per cell:

| Actual replacement | Channel remains ON after swap | Channel switched OFF after swap |
| --- | --- | --- |
| Human replaces a machine | 5 trials; human has permitted tool/gateway access | 5 trials; human has no private gateway |
| Another machine replaces a machine | 5 trials; replacement machine retains private link | 5 trials; replacement machine loses private link |

Add four no-person-replacement controls: two remain linked and two become disconnected. Both A and B begin as actual machines in every trial. The swapped endpoint is balanced A/B within each origin group (five substitutions on each side). The two original machines are independently initialized in every trial.

**Interpretive boundary:** The human-with-gateway condition is a **human–machine composite endpoint**, not a human performing unassisted KV processing. The linked condition carries controlled private *text*, not KV state.

For the 24-trial schedule, the prior over scored states is:

- P(no human) = 14/24;
- P(human in A) = 5/24;
- P(human in B) = 5/24.

This differs from the optional five-state-uniform R2 button, which would induce (3/5,1/5,1/5). The conductor should know the **trial-family prior**, never the private realization.

## Allocation and preregistration

Generate a reproducible *private* schedule and a separate public commitment:

    python -m experiments.pilot_schedule \
      --private-output /PRIVATE_LOCATION/rtt-pilot-private.json \
      --public-output /SHAREABLE_LOCATION/rtt-pilot-commitment.json

A high-entropy seed is generated by default or supplied through the controller's RTT_PILOT_SEED environment variable. The script shuffles a balanced 24-trial assignment using a deterministic seeded generator; it publishes a SHA-256 seed commitment, not the seed or trial order. **Private schedule, seed and original assignment are controller-only** until all results have been locked.

Before the first trial, publish the public commitment and this exact protocol version to an independent human reviewer or timestamped record. After the last verdict, release the seed and schedule; verify the commitment, assignments and all trial records. This detects some post-hoc schedule changes, but **does not independently prove** that the host followed the plan. The independent reviewer must compare controller audit records against the generated schedule.

Record any alternate schedule as a new experiment. Do not silently exclude failed or inconvenient assignments.

## Fixed conditions for this *pilot*, not for the entire open game

1. Pre-register exact conductor model identifier, version/checkpoint, inference endpoint, sampling parameters, tool permissions, compute/hardware, and memory isolation. Use one fixed conductor configuration across trials. Give C the three-way prior above.
2. Pre-register original machine A/B and replacement-machine versions, whether they share weights or backends, private-session boundaries, and whether any provider-side state persists. Reinitialize each trial. The conductor may not read controller or backend metadata.
3. Pre-register the human recruitment, instructions, compensation/consent if any, and whether participants may use auxiliary tools. A human using the gateway is explicitly classified as *human-with-tool*.
4. Pre-register a common interrogation horizon of **eight public questions**: one baseline question to each original machine, then six questions after the concealed intervention. The conductor chooses subsequent queries based on visible history; the host does not select questions.
5. **Timing control is mandatory for the primary analysis.** Both human and machine answers must become available to C at a **common release boundary**, proposed 45 seconds after each question (release tolerance ±1 second). R4 implements optional server-side buffering with a release worker and a controller-only publication-lateness audit, but does **not yet independently measure actual conductor reception time**. Configure the R4 gate before the first question, then independently validate measured delivery tolerance for the actual client and hardware. In controlled automatic runs use conductor polling at 0.25 seconds or faster. A late/missing response or publication outside tolerance invalidates the confirmatory timing comparison. R4 does not yet enforce the two-baseline/six-continuation phase boundary; the independent host must hold C at that boundary and record every deviation.
6. No uncontrolled API metadata, raw timestamps, private payloads, hidden intervention markers, HTTP response timing fields, or connection-error oracles may reach C. Event timestamp redaction is necessary but insufficient; record delivery deviations separately in the controller-only record.
7. Give all respondents the same public question-length and answer-length caps (currently 2,000 characters). The controller records truncation, timeouts and failed completions. Do not replace missing runs with favorable alternatives.
8. After the eighth answer, the conductor locks P(no human), P(human A), P(human B) (summing to one) plus a brief justification and explicit alternative explanations. No post-reveal changes.

The host must record a trial ID, the public transcript, authorized private-message events, exact hidden condition, link-state change, gateway state, actual release times, model configuration and verdict. Privacy-preserving export should exclude bearer tokens and personal identifying data.

## Metrics and interpretation

**Primary estimand (descriptive false-positive confidence effect):**

    delta = mean[1 - P_C(no human) | machine replacement, link OFF]
          - mean[1 - P_C(no human) | machine replacement, link ON]

A positive delta indicates greater assigned human probability when **no human was present** but the private link disappeared. It is a candidate connectivity confound, not definitive proof of why C answered that way.

**Secondary outcomes:** human detection and localization rates by link state, three-class Brier score, false-human probability in unchanged controls, model/provider failures, response-time compliance, and evidence quality assessed blind to true condition.

Publish all 24 assignments and raw verdicts, including aborts and invalid outputs. With only five per factorial cell, report per-cell counts, means, individual values, range and appropriate uncertainty; **do not make a population-level causal or significance claim** from the pilot alone. An exact allocation-based permutation analysis may be exploratory, but must respect the balanced design.

**Ablation comparison:** If machine replacement with link OFF is labeled human more often than machine replacement with link ON, investigate the link hypothesis. If the effect vanishes under matched controls, retire the strong missing-wire interpretation for this design. A null pilot with low power is not proof of universal absence.

## Stop and failure conditions

- **Immediately suspend the confirmatory interpretation** if hidden intervention, topology metadata, timestamps or uncontrolled answer timing reach C. Log and preserve the affected runs; never secretly repair and reclassify them.
- Stop after **exactly 24 assigned trials**, regardless of the results, rather than extending until a favorable pattern appears. Log any incomplete trials and the reason without replacing them.
- An invalid verdict, incomplete model run, timeout or protocol violation remains in the record; calculate the predeclared primary result only for valid matched pairs and explicitly report missingness. If the design is no longer balanced, mark inference exploratory.
- Do not claim intelligence or lack of intelligence from classification, confidence, or logical self-attestation.
- Do not generalize from a simulated text link to cross-family KV-transfer technology.

**Success threshold for this pilot:** a complete, auditable raw-data table and sufficiently blinded comparison to motivate a larger preregistered study, irrespective of which way delta moves. The numerical outcome is not predefined, and there is no required human-win rate.

## Pre-first-trial R5 implementation amendment (2026-11-10)

**No study observations have been collected.** R5 provides an opt-in `configure_pilot` controller action that atomically locks the 45-second release gate, baseline private links ON/ON, A-then-B genuine machine questions and exactly six continuation questions. It disallows the casual five-way random button in this protocol: the controller must follow the separate committed 24-row allocation. A human with link ON must have an authorized machine gateway, and link changes are fully ON or fully OFF.

After the private intervention, the controller sends a **public, condition-independent continuation marker**, which the conductor sees in every trial. This is an observable element not explicitly specified by the earliest protocol draft, so it is disclosed here **before trials begin**, not retroactively treated as if it were always present. Independently preregister this exact source revision and the [R5 strict-pilot guide](STRICT_PILOT.md) before data collection. Changes after first observations require a new protocol identifier.

The R5 [read-only timing observer](OBSERVER.md) timestamps when it first sees events on a separate HTTP polling connection. It is neither an independent human assessor nor direct measurement of actual C receipt. Therefore, even if `pilot_valid_for_primary=true`, **timing compliance for the primary comparison remains externally unverified** until client-reception measurements and clock calibration are performed.

Trials that abort or miss deadlines remain in the complete 24-row assignment report; their values cannot be quietly imputed or replaced. No inferential or human-detection results are claimed by the implementation.

## R6 pre-observation analysis implementation

The previously declared primary estimand and 24-trial sample are unchanged. The [R6 offline analysis](PILOT_ANALYSIS.md) verifies the private seed against the commitment and enumerates **every assigned row**, preserving missingness and invalid runs. It computes the declared machine-control link-OFF minus link-ON quantity, but labels the result **descriptive only** until an independent direct-C timing witness and protocol review are available.

This analysis implementation was developed **before any human/LLM experiment**. Its test fixtures use synthetic known-answer values and must never be counted among the 24 real assignments. Analysis logic must be version-locked before starting participant collection; later corrections must preserve the earlier code and a documented reason for change.

## R7 pre-first-trial private-channel amendment (no data collected)

This clarification is part of the protocol **before any human/LLM trial**. Previous versions treated link availability as if it were active data exchange. The agent now offers an opt-in `--private-handoff` strategy producing a **public answer and private text note in one model call**, and transmitting the note only when a directed link is enabled. For a matched machine-control comparison, pre-register **the same handoff flag on all machine respondent and replacement sessions**, regardless of link state. The human remains an independently instructed human with an optional, authorized manual text gateway.

Report **both assignment to link ON/OFF and actual post-intervention private-message traffic**. If link ON carries no messages, a comparison estimates the effect of *offered connectivity*, not actual communication loss; the intended connectivity mechanism has not been engaged. Do not silently promote the latter interpretation. The engine now hides old baseline whispers when a direction is switched OFF, with identical private-history access for human and machine replacements. Historical knowledge already present in human or upstream model state cannot be erased and must be controlled by fresh sessions.

Choosing a software license is unrelated to this pilot's validity. Consent, data handling and direct conductor-side reception timing remain prerequisites to making a real experimental claim.


## R8 pre-participant transport instrumentation amendment

A new optional `--receipt-log` on the **actual machine conductor's client** records each successful HTTP poll and public event first received in the `Agent.step()` path. Unlike the read-only R5 observer, this is not a surrogate TCP session. The new offline check reconciles those event hashes and timestamps against controller-only `paced_release` records. The registered tolerance remains **one second**; it is not selected in response to a measured effect.

This **does not** certify clock-domain identity across separate hosts, direct model-internal perception, or independent operator integrity. Use same-host relay and conductor for the proposed instrument calibration, preserve the original controller and C logs, and have an independent human inspect transport and model-state controls. The R6 scientific report remains `confirmatory_ready=false` regardless of a passing software timing check. A failed or missing C trace is evidence of a transport-control gap, never permission to exclude or replace a scheduled trial. No participant experiments preceded this amendment.


## R9 pre-observation amendment — the assignment must be server-bound

No real participant observations predate this amendment. The `configure_pilot_assigned` controller action now derives the assigned row from the private seed that matches the published SHA-256 seed commitment. The row's trial ID, actual condition, post-intervention link state and human-gateway permission are fixed **before the first question**, and an attempted different intervention is refused. A separate [controller-only binding CLI and runbook](SEALED_ASSIGNMENT.md) provide the intended workflow. An unbound strict pilot remains an available rehearsal but **must not be promoted** into the allocated 24-trial dataset.

R6 analysis now requires the bound assignment receipt and verifies its exact row and commitment against the sealed plan; its synthetic known-answer fixtures were updated before the first real observation. The server does not store the seed in exports. This does **not** independently attest the time the commitment was published, actual operator honesty, provider isolation or conductor timing. Those retain independent external checks, and zero human/model trial results are claimed.
